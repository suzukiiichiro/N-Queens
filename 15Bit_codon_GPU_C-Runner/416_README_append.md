## 416 — N≥25 のフレーム「425」：avail を持たず pop で再計算する（N=24 で費用を測る、本番値は不変）

### なぜ

424 の形（col N−2＋avail N−2＋ld[1..N−4]＝3N−8 ビット）は N=24 で 64 ビットちょうど。N=25 は 67 で 3 ビット足りない。
avail のビット 0 が常に 0（残りは取った bit より上）、rd のビット 31 が常に 0（I3）を使っても 65 で、なお 1 ビット足りない。

avail は冗長：フレームの avail は常に「その節の候補集合のうち、最後に取った bit より上」で、候補集合は節の状態から `~(ld|rd|col)` で出る
（col が ~bm と定数 2 ビットを持つので bm のマスクは不要。ホストの `free` も `bm & ~(ld|rd|col)`（413 ノート、`416_bitcheck.py` の I6 で全件確認）。
j マークは bit 0 を消すだけで、取った bit より下。`nld |= child_jmark` で ld の bit 0 が立っても bit 0 の話）。
よって **フレームは最後に取った bit の index（5 ビット）を持てばよく、pop で `avail = ~(ld|rd|col) & (0xFFFFFFFE << idx)`** と再計算できる。

415 ノートの「最後に取った bit は pop の瞬間に子の col ^ 親の col で出る」は**誤り**：pop で離れる節はフレームの節より何段も下にあり得る
（候補 1 つの節は push しないので、戻り先は親とは限らない）。その差は 1 ビットではなく、どの bit がフレームで取られたかは分からない。index なら分かる。

### 425 配置（固定フィールド、N≤29 で正確）

```
425:  A (u64) = col[0..26] | idx << 27 | (ld >> 1) << 32      （27 + 5 + 32 = 64）
      B (u32) = (rd & ~1) | ld[0]                              （403-r7 の綴り）
push: idx = bfind(bit)                                         ← FLO 1 命令（インライン PTX、bit は 1 ホット）
      A.lo = (col & 0x7FFFFFF) | idx << 27                     ← SHL + LOP3
      A.hi = ld >> 1                                           ← SHR（死にビット >= N-3 もそのまま保存）
      B    = lop3(rd, ld, 1, 0xD8)                             ← 424 と同じ            [424: 5 → 425: 6]
pop:  colm = A.lo & 0x7FFFFFF ; cur_col = colm | nbm2 ; depth = popc(colm) − base   ← 424 と同じ
      cur_ld = lop3(A.hi << 1, B, 1, 0xD8) ; cur_rd = B                          ← 424 の A>>43 と同じ 2 命令
      avail  = lop3(ld, rd, col, 0x01) & (0xFFFFFFFE << (A.lo >> 27))            ← idx 1 + LOP3 + SHL + AND = 4
                                                                                    [424 の avail 取り出し 2 → +2]
```

ld の死にビット（≥N−3）はマスクせず保存・復元する：ld が読まれる場所は全て左シフト後で col の定数ビット（N−2、N−1、盤外）の下に入るので結果に出ない（415 の読み）。
col は 27 ビット固定（N<29 では bit N−2..26 は定数 1 で、`depth_base` も同じマスクで数えるので深さは合う）。一般形は col (N−2)＋idx 5＋ld 32 ≤ 64 → **N≤29**。
祖先段数は **424 と同じ 15**（N=24 比較でフレーム数を変えないため）。N=25（417）は `required_maxd` を数えてから上げる（17 → 16 段＝192 B の見込み）。

命令数の読み（律速の仮定：恒久ルール 22、pop／push の 1 命令 ≈ 0.5%）：pop +2、push +1 → **+1〜2%**。<425> のループは 107＋2〜4。
