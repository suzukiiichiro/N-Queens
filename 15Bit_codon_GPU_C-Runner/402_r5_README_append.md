### r5が変えるもの — `.py` の1行

maxd14テーブル行の `env_prefix`：

```
"NQ_EXTRA_CTX=1 "  →  "NQ_EXTRA_CTX=1 NQ_HELPER_CTX=1 NQ_HELPER_MB=128 "
```

`NQ_EXTRA_CTX=1` は9/9以降不活性（401-r4 H1）だが**残す**——外すのは2つ目の変更で、
G1mはそれが在る状態で測った値。`.cu` は402-r4のリネーム（`#include` 以降バイト一致）。
Pyの実行行差分は3行（`VERSION_TAG`／`REV_TAG`／テーブル行）。395c-r6と同じく、処遇を
`env_prefix` に置くのは `dispatch.log` に記録が残るため。

### 事前登録予測（実測前に固定）

1. **U1（ハード）**: `dispatch.log` に `env_prefix=NQ_MAX_BLOCKS=960 NQ_EXTRA_CTX=1
   NQ_HELPER_CTX=1 NQ_HELPER_MB=128`、CRunnerログに `[gpu-helper] helpers=1 helper_mb=128`
   と `MAX_BLOCKS=960`（全走行・全Nで）。
2. **U2**: G21a・G21b が 109,459（r4 G1m）の ±0.15%、かつ互いに0.05%以内。
3. **U3**: `-g 19 21` で N=19/20/21 がすべてオラクル一致（ハード）。N=20 の `kernel_ms`
   は 16,482（401-r3 Gd、ヘルパーなし）の ±1.0%（情報。ヘルパー状態のN=20は未測定）。
4. **U4**: 全セルの平均SMクロックが1710の±2%。

**採用**: U1・U2成立で本番 ＝ **109,46x ms（1:49.5）**。README本文の本番値を更新する。

### この先

403：N=22向けの12バイト分割（ld N−1ビット、rd 31ビットの死にビットを使って
3×22＋30＝96ビット、固定幅22でN≤22対応）。ゲートは402と同じ順に加えて、N=22で
オラクル 2,691,008,701,644 と 401_r4 バイナリとのスレッド別バイト一致。通れば N=22 で
MB=800対960、ヘルパーあり／なしの初測定。
