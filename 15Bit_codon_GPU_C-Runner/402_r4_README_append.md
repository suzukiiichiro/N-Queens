## 402-r4 — ホルダーをバイナリの中へ（`NQ_HELPER_CTX`、ホスト側のみ）

### 402-r3の結果（N=21、MB=960、外部ホルダー、全10走行オラクル一致、全セル1710 MHz）

| セル | ホルダー | ctx | kernel_ms | vs H0 |
|---|---|---:|---:|---:|
| G0（`-g`） | なし | 2 | 111,964.6 | +0.003% |
| H0 | 1 | 2 | 111,961.4 | — |
| **H2** | 2 | 3 | **109,969.3** | **−1.78%** |
| **Gh**（`-g`＋ホルダー1） | 1 | 3 | **109,973.5** | **−1.78%**（H2と0.004%） |
| H3 | 3 | 4 | 109,468.2 | −2.23% |
| H2b | 0＋128 MB | 3 | 109,416.8 | −2.27% |
| H2c | 0＋384 MB | 3 | 109,482.4 | −2.21% |

800では幅128 MiB未満の切り欠き（−0.29%）だったものが、960では**段差**：第3コンテキストで
−1.78%、さらに何を足しても（4ctx／+128 MB／+384 MB）一様に約−2.2%で平坦。S1〜S3成立、
S4（4ctxは3ctxより良くない）は反証。採用則成立（複製0.002%／0.011%）。**機構は未特定。**

### r4が作るもの

`NQ_HELPER_CTX=<n>`：親がCUDAに触れる前に子プロセスを n 個 fork する。子は自分の
コンテキストを作り（`cudaFree(0)`）、`NQ_HELPER_MB` MiB をtouchして確保し、親が終了
するまでパイプで待つ（`PR_SET_PDEATHSIG` を保険に）。親は各子の準備完了バイトを待って
から進むので、最初の `cudaMalloc` の前に状態ができている。親は終了時にパイプを閉じて
子を `waitpid` するので、GPU上に何も残らない。未設定なら何もforkせず402-r3と同一。

- なぜ子プロセスか：401-r4 H1（自プロセスctx、−0.001%）対 H2（他プロセス、−0.288%）。
  **他プロセスのコンテキストだけが数えられる**（理由は不明のまま）。
- カーネル領域は402のまま（`122b3319…`）。コード領域差分 removed=0 added=87。
  CPUテストの `main()` は無変更。
- 手元検証：fork／pipe／reapの論理をCUDAスタブで模擬し、子2個が親の作業中は生存し、
  親のパイプclose後にreapされることを確認。範囲外（9）は拒否。

### セル（全てN=21、MB=960既定、402-r4バイナリ）

`-g` セルはハーネスの環境変数 `NQ_HELPER_*` を `os.system` 経由で継承する（395c-r5の
Gxと同じ経路）。**テーブルの `env_prefix` は変えない**——採用は402-r5で。

| セル | 経路 | `NQ_HELPER_CTX` | `NQ_HELPER_MB` | 期待 |
|---|---|---:|---:|---|
| G0 | `-g 21 21` | 0 | — | 111,965（r3 G0） |
| G1 | `-g 21 21` | 1 | 0 | ≈109,97x（Gh相当） |
| G1m | `-g 21 21` | 1 | 128 | ≈109,4xx（H2b相当） |
| G2 | `-g 21 21` | 2 | 0 | ≈109,4xx（H3相当） |
| **D1** | 直接、外部ホルダーなし | 1 | 0 | **111,961（r3 H0）：子1個＝外部ホルダー1本** |
| **D2** | 直接、外部ホルダーなし | 2 | 0 | **109,969（r3 H2）** |

1周目 G0 G1 G1m G2 D1 D2、2周目 G2 G1m G1 G0（反転）。10走行、約22分。GPU空きゲートは
**何も無いこと**を要求（r4に外部ホルダーは無い）。各セル後に居残りを確認。全セル
クロック採取、オラクルゲート、`MAX_BLOCKS=960` と `[gpu-helper] helpers=<n>` をゲート。

### `*_README_append.md` との照合

395c-r4（`NQ_EXTRA_CTX`、自プロセス内）、395c-r5（Gh：`-g` の傍らの外部ホルダー、Gx：環境
変数の継承）、401-r4（自プロセスctxは不活性）、402-r3（960の段差）に該当あり。
**子プロセスにコンテキストを持たせる形は該当なし。**

### 事前登録予測（実測前に固定）

1. **T1（ハード）**: G0 が 111,965 の ±0.15%、`[gpu-helper] helpers=0`。
2. **T2（ハード・機構）**: D1 が 111,961（r3 H0）の ±0.15%、D2 が 109,969（r3 H2）の ±0.15%
   —— forkした子1個＝外部ホルダー1本。**落ちたら子プロセスはホルダーの代わりにならず、
   本番は外部ホルダーで運用するしかない。**
3. **T3（表明する予測）**: G1 ≤ G0 − 1.5%（約109,97x）。
4. **T4（表明する予測）**: G1m と G2 はともに G0 − 2.0% 以下で、互いに0.15%以内。
5. **T5**: `-g` 各構成の2回が0.05%以内。
6. **T6**: どのセルの後にもcomputeプロセスが残らない。
7. **T7**: 全セルの平均SMクロックが1710の±2%。

**採用則**: 勝者が G0 − 1.5% 以下で、T2とT5を満たすとき。同点判定：|G1m − G2| ≤ 0.15% なら
G1m（3ctx、子1個）を G2（4ctx、子2個）より優先。**402-r5**で勝者の `NQ_HELPER_*` をテーブルの
`env_prefix` に入れ（Pyの実行行変更）、`-g 21 21` を1回測り直す。本リビジョンで採用する
ものは無い。

### 四点の同一性

- `402_r4_kernel_maxd14.cu`: 402-r3に対しホスト側のヘルパーブロック（`main()` の argv 直後、
  ファイルを開く前）と終了時のreapを追加。ハーネスは「カーネル領域sha不変」「fork が最初の
  ファイル・CUDA呼び出しより前」「`if (want > 0)` ガード」「`_exit`」「`PR_SET_PDEATHSIG`」
  「`waitpid`」「CPUビルドが通ること」を静的にゲートする。
- `402_r4Py_kernel_maxd14_final.py`: 402-r3Pyから実行行3行。`env_prefix` は `NQ_EXTRA_CTX=1 `
  のまま。
- `402_r4_validate.sh`: 新規。

```
STATIC_ONLY=1 bash 402_r4_validate.sh     # OK=18
              bash 402_r4_validate.sh     # 約22分
ROUND2=0      bash 402_r4_validate.sh     # 1周のみ（採用判定はしない）
```

**事前条件**: `402_r3Py_kernel_maxd14_final.py`・`402_r3_kernel_maxd14.cu`（指紋の比較元）、
`rev386_validation_helpers.py`、gcc。N≤21専用は変わらない。
