### 404-r3の変更

メインループの2行：

```
if (future_check_mask != 0u) {          →   {
    if (fc_flag != 0u) {                →       if (((future_check_mask >> cur_depth) & 1u) != 0u) {
```

`future_check_mask` はスケジュール解読時に深さごとに1ビット立てているので、ニブルのフラグと
「マスクが0でない」の2段判定を、深さビット1回の判定にする。ルートの高速経路は不変。
カーネルは探索（d5）・診断セル（L5、C2、C3）で測ったものと同じ。

**前例**：242が同じ形をCodon JITで試して+1.3%で不採用（7分台の1走行で判定、SASSなし）。
今回は診断セルで先に測り、スレッド別バイト一致も確認してから本番候補にした。

- `.cu`：404_r2比 コード領域 **removed=2 added=2**。404_r2に生成器（C）を適用した結果とバイト一致。
- `.py`：404_r2Py（本番）の純粋リネーム、実行行3行。
- ハーネス：`404_r3_validate.sh`。
