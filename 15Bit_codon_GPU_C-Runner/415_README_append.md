## 415 — N=24：12 バイト配置 424 と祖先 15 段（1 バイナリで N≤24）

本番は 414（値は 413）のまま。このリビジョンは N=24 の**正しさと最初の測定**で、N=24 の本番値は 415-r3（フル実行、見込み 20〜25 時間）で出す。

### ビット勘定の読み直し — 413 の「97 ビット」は数え漏れだった

413 は ld の死にビットを bit N−1 の 1 本と数え、N=24 では col 22＋avail 22＋ld 23＋rd 30＝97 ＞ 96 として 16 B フレームを見込んでいた。
カーネルを読み直すと ld が読まれる場所は 3 つで、**すべて左シフト後**：

| 読まれる場所 | 式 | ld の bit b が効く先 |
|---|---|---|
| pop 後の `cur_x`（406 H1） | `(ld<<1) \| (rd>>1) \| col` | cur_x の bit b+1 |
| 降下 | `nld = (ld\|bit) << step`（step 1、マークで 2〜3） | 子の ld の bit b+step |
| future_check | `(nld<<1) \| (nrd>>1) \| ncol` | bit b+2 以上 |

col の bit N−2・N−1 は常に 1（ホストの `col |= ~small_mask`、以後 `| bit` で増えるだけ）、bit ≥ N は 405 以降 col が `~bm` を持つので常に 1。
よって cur_x の bit N−2 以上は col が決め、**ld の bit N−3 以上は読まれない**（左へしか動かないので二度と下りてこない）。
生きている ld は **bit 0..N−4 の N−3 ビット**。rd は右へ動く（bit 0 死に、盤外ビットは生きて下りてくる）ので bit 1..30 のまま：
N=24 でも `(1<<(N1−j))<<(N2−start)` の bit は `45−j−start`、条件 `j ≥ 15−start` で ≤30；生の rd は u32>>1；`bK = kt·n4` は bit N−3 以下。
（423 は ld[1..22] を保存していたが、必要なのは ld[1..19]。余分は無害。）

`415_bitcheck.py` が N=24 の 361 ダンプ全件でホスト側の不変量（col の bit 22・23 常に 1、free のその bit 常に 0、rd 最大 bit ≤30、ld 盤内）を
確認する（結果はこの節の次の `_append` に記載）。カーネル内の部分（rd は下へ、ld は上へしか動かない、col の定数ビットが cur_x を覆う）は上の読み。

### 424 配置 — 403 の A ワードそのまま、pop は 423 の形

```
424:  A (u64) = col[0..21] | avail[0..21] << 22 | ld[1..20] << 44      （22+22+20 = 64 ちょうど）
      B (u32) = (rd & ~1) | ld[0]                                        （403-r7 の綴り）
push: A = (col & 0x3FFFFF) | avail<<22 | ((ld<<11) & 0xFFFFF000)<<32  ← 403 と同じ式
      B = lop3(rd, ld, 1, 0xD8)
pop:  colm = A & 0x3FFFFF ; cur_col = colm | nbm2   （nbm2 = ~bm | 定数 2 ビット、423 と同じ）
      cur_avail = (A >> 22) & 0x3FFFFF
      cur_ld = lop3(A >> 43, B, 1, 0xD8)   ← A>>43 の bit 0 は avail[21] の屑だが B の ld[0] で上書きされる
      cur_rd = B
```

フィールドごとにシフト 1＋LOP3 1。**423 と命令数が同じ**なので `<424>` のループは 107 前後（表明 ≤110）。祖先 15 段で 180 B
（ptxas が 168→176 に丸めた前例があるので 192 B の可能性。≤192・spill 0 がハード）。一般形：A＝2(N−2)＋(N−4)＝3N−8 ≤ 64 → **N ≤ 24 がこの形の限界**。

### N ≥ 25 への道筋（このリビジョンでは測らない）

`avail` は冗長。DFS は候補を下位ビットから順に取るので、フレームの avail ＝「その行の候補集合 `~(ld|rd|col) & bm` のうち、最後に選んだ子の bit より上」。
最後に選んだ子の bit は pop の瞬間に `子の col ^ 親の col`（1 ビット差）で出るので、**保存不要**。pop で再計算すると +3〜4 命令（恒久ルール 22 の pop 軸に
逆らう。見込み +1.5〜2%）だが、A ＝ col (N−2)＋ld (N−3 ビット、再計算に bit N−3 が要るので 1 本増える) ＝ 2N−5 ≤ 64 → **N ≤ 34**。
16 B フレーム（240 B、L1 の論理で MB 640）より安い見込み。**N=24 で 424 と同じ入力・バイト一致で費用を測れる**。
