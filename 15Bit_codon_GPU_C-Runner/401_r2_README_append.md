## 401-r2 — Nを上げてkの交絡を外し、今夜の決着をつける

### 401の読みを歪めた、私のハーネスの誤り2つ

**(1) 作業集合の計算が、SMあたり16ブロックの上限を無視していました。**

`BLOCK=32` では1ブロック=1ワープなので、**`MAX_BLOCKS` が1280を超えても常駐
ワープは増えません**（余剰ブロックは待つだけ）。401の表の MB>1280 の行は、
存在しない作業集合を報告していました。**`L2 FAILED`（非単調）の判定は、まるごと
この誤りから出ています。**

作業集合が実際に変化する 800〜1280 の範囲では単調です。

```
2154.7 / 2301.0 / 2279.5 / 2433.5 / 2854.0 / 3032.6 / 3304.5 ms
```

ncuが裏付けます。MB=2560 の Achieved Occupancy は 30.25%、warps/sched 3.75
= **15 warps/SM** であって32ではありません。400-r2の「stride 81,920 で
10,729 ms」も同じ理由で**別の点**でした——あれは `64:1280`、16ブロック×2ワープ
= **32 warps/SM・208 KB** です。

**(2) `warps/SM` と `k_per_thread` は、1つのNでは分離できません。**

どちらもstrideで決まります。N=19で10→16 warps/SMにすると k は 35.0→21.9 に
落ちるので、**+53%という罰則はL1効果とテール効果の混合**であり、L5の棄却は
交絡しています。

r2では `blocks/SM ≤ 16` の上限を実装し、**`k_per_thread` を表の列に出します。**

### 401から生き残るもの

**L1曲線。これはSM単位の容量特性でNに依りません。**

| 作業集合 | L1ヒット率 |
|---:|---:|
| 65.0 KB | **99.51%** |
| 78.0 KB | 98.56% |
| 104.0 KB | 97.68% |

**本番点は既に崖の縁**で、ローカル用の実効L1は70 KB前後。私のL3予測
（99%割れは80〜120 KB）は外れで、実際は **71.5〜78.0 KB** のあいだでした。

### r2がすること

同じ梯子を **N=19 / N=20 / N=21** で登ります。Nを上げると各段のkが上がります。

| warps/SM | k(N=19) | k(N=20) | **k(N=21)** |
|---:|---:|---:|---:|
| 10 | 35.0 | 53.5 | 79.1 |
| 12 | 29.2 | 44.6 | 65.9 |
| 14 | 25.0 | 38.2 | 56.5 |
| **16** | 21.9 | 33.4 | **49.4** |

> **N=21の16ワープ段は、N=19のベースライン段（k=35.0）よりkが多い。**

そこでもなお遅ければ、**ワープ増は本当に割に合わず、104バイト詰め替えは書く
べきではありません。** 速ければ、L5の棄却はデバッグ規模の人工物であり、
**詰め替えが復活します。**

ncuは使いません。396でncuが133秒のN=21カーネルを完走できないことが判明して
おり、容量の問いは401のL1曲線で既に足りています。

### 事前登録予測（実測前に固定）

1. **M1**: N=19 の MB=800 が 2,154.677 ms の ±0.5%（セッションアンカー）。
2. **M2**: MB=1280 の罰則は N が上がるほど小さくなる
   （罰則 N=19 > N=20 > N=21）。**交絡の存在そのものの検定**です。
   単調に縮まなければ「kが効いている」という説明が誤りで、機構は未特定に戻ります。
3. **M3（本リビジョンの決定事項）**: **表明する予測——N=21でも MB=1280 は
   MB=800 より遅い。ただし罰則は20%未満。**
   **速ければ L5の棄却は誤判定で、104バイト案が復活します。**
4. **M4**: N=21の罰則が5%以下なら、フレーム縮小で反転しうるので、もう1リビジョン
   の価値があります。**20%以上なら軸は死んでいます**——その場合 `wait` 48% は
   「ワープを増やす」ではなく「**内側ループの依存鎖を短くする**」方向で攻めます。

全走行がオラクルゲート下です。

### 所要

4点 × 2反復 × 3つのN ≈ **カーネル25分**＋生成とビルド4分。反復2回はノイズ
フロア0.02%に対して十分です。急ぐなら削れます。

```
STATIC_ONLY=1 bash 401_r2_validate.sh   # OK=12
              bash 401_r2_validate.sh   # 約29分
N_LIST="19 20" bash 401_r2_validate.sh  # 約4分（決定セルなし）
REPS=1 bash 401_r2_validate.sh          # 半分に
```

401の予算計算より、99%ヒットを保つ最大作業集合は **71.5 KB**。104バイトなら
**704 threads/SM = 22 warps/SM**（`BLOCK≥64` が必要）、現行の10に対して2.2倍。

**ただし着手はM3が通った場合のみです。** そして着手したら、397を止めたのと同じ
**全2,025,282レコードのバイト一致ゲート**を先に通します。
