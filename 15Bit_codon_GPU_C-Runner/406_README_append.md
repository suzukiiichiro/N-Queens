## 406 — `cur_x` を持ち越す：`nf` を `bit` の2段後に（H1）

405の結果と採用は `405_results_README_append.md` に記録済み（N=21 106,925 ms／N=22 935,956 ms）。

### 静的読み（405の `<403>` ステップ、マークなし、GPUゼロ）

405は命令数を動かさず、`nf == 0` の分岐を1段早めて−0.4%だった。そこで分岐の手前に残る段を数えた。

| 段 | 内容 | 命令 |
|---|---|---|
| s1 | `-avail` | IMAD.MOV |
| s2 | `bit = avail & -avail` | LOP3 |
| s3 | `ld\|bit`、`rd\|bit`、`col\|bit` | LOP3 ×3 |
| s4 | `<< 1`、`>> 1` | IMAD.SHL、SHF |
| s5 | `nf = ~(nld \| nrd \| ncol)` | LOP3 `0x01` |
| s6・s7 | `nf != 0`、分岐 | ISETP、BRA |

- s1・s2は縮まない（最下位ビットの抽出を1命令にする形がない）。
- s3＋s4は1段にできる。シフトはORに分配できるので、`cur_x = (ld << 1) | (rd >> 1) | col` を状態として持てば
  `nf = ~((cur_x | bit) | (bit << 1) | (bit >> 1))`。値は従来とビット一致。
- 代償：`cur_x` を降下とpopのたびに作り直す（シフト2本＋LOP3 1本）。README該当なし。
