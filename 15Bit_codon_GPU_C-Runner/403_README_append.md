## 403 — 12バイトフレームをN≤22に（死んでいる2ビットで足りない3ビットを賄う）

### 402-r5で確定したこと（2026-09-28）

`-g 21 21` ＝ **109,437 ms（1:49.4）**。12バイトフレーム・MAX_BLOCKS 960・forkした
ヘルパー1個＋128 MB。今日の出発点133,58xから−18.1%。`-g 19 21` もヘルパー付きで全N
オラクル一致。

### 402の限界と403の分割

402は3×21ビット（63）で **N≤21専用**だった。N=22は col 22 ＋ avail 22 ＋ ld 22 ＝ 66 で
入らない。しかしコードを読むと、保存する値に**死んでいるビットが2つ**ある。

- **ldの bit N−1 は死んでいる**：保存したldの唯一の用途は `(ld|bit) << step`（step≥1）の
  後に `bm` でマスク。bit N−1 は必ず盤外へ出る。→ ldは **N−1ビット**（398の「ld 20」と整合）。
- **rdの bit 0 は死んでいる**：保存したrdの唯一の用途は `(rd|bit) >> step`（step≥1）。
  bit 0 は消える。→ rdは **31ビット**（**新規の主張。`*_README_append.md` に該当なし**）。

```
word A (u64) = col(22) | avail(22)<<22 | ld[0..19]<<44
word B (u32) = (rd & ~1) | ld[20]
```

22＋22＋21＋31＝**96ビット＝12バイト**、固定幅22で N≤22。push／popとも402より
AND/OR/shift が1つずつ増えるだけで、ローカルアクセスは push 2／pop 2、フレームは160 Bのまま。
両 `main()` は N>22 を rc=3 で拒否（22は通るので、素の `-g` は22まで走り23で止まる）。

**手元検証**：合成N=22（250レコード、解21,747,412）とN=21（150レコード）で、**ldの盤外
ビットと rd の bit 0／bit 24〜31 にわざとゴミを入れて**、401_r4（非圧縮）と403のCPU出力が
バイト一致。N=23は rc=3。コード領域差分 removed=21 added=33。

### `*_README_append.md` との照合

397（rdマスクで棄却——上位ビットが生きている。本リビジョンは上位を全部残し、下位1ビット
だけ落とす）、398（必要幅98ビット）、402（depthをレジスタへ）。
