## 403-r2b — 403_r2の`<402>`実体は402_r5と同じSASSか（診断のみ、GPU時間ゼロ）

### 403-r2で確定したこと（2026-09-29）

全5走行オラクル一致、全セル1710 MHz、居残りゼロ。ハードゲートは全通過：Y1 2実体とも
160 B／spill 0／40レジスタ・ptxasエントリ2、Y2 CPU等価3組一致、Y3 拒否2種 rc=3、
Y4 X1・X3ともX0とスレッド別バイト一致。

| セル | | kernel_ms | 対 |
|---|---|---:|---|
| X0 | 402_r5 直接 | 109,457.8 | アンカー109,437比 +0.019% |
| X1 | 403_r2 auto（402レイアウト） | 109,592.7 | **X0比 +0.123%**（Y5 成立、帯の縁） |
| X3 | 403_r2 `NQ_LAYOUT=403` | 112,079.5 | X0比 ×1.0240（**Y6 不成立**：登録帯[1.025, 1.031]を下に外れ） |
| G21 | `-g 21 21` | 109,595.6 | 109,437比 +0.145%（Y7 成立、帯の縁）、X1比 +0.003% |
| G22 | `-g 22 22` | 983,926 | 403の987,065比 −0.318%（Y8 成立） |

採用則（Y0〜Y5・Y7）は形式的に成立。しかし**+0.12%は本物**と読む：これまでの最大セッション内
ノイズ0.04%の3倍、X1とG21が0.003%で一致し、X0はアンカーと0.019%で一致。402分岐は402_r5と
文字一致なので、差があるならSASS（強制インライン／テンプレート文脈での命令選択・スケジューリング）
か、コード配置（cubin内にカーネルが2つ）。採用の前にそれを確かめる。

### 403-r2bの分割

コード変更なし。`.cu`／`.py` は403_r2の純粋リネーム（Pyの実行行3行：VERSION_TAG／REV_TAG／
テーブル行）。ハーネスが `cuobjdump -sass` で

- **Z3**：`402_r5_kernel_maxd14` のカーネル 対 `403_r2b_kernel_maxd14` の `<402>` 実体
- **Z4**（対照）：`403_kernel_maxd14` のカーネル 対 `403_r2b_kernel_maxd14` の `<403>` 実体

を、アドレス列とエンコーディングを除いた命令列で比較する。判定は3段：完全一致（分岐先込み）／
分岐先を除いて一致（同じコード、オフセット違い）／相違（最初の差分命令12行とオペコード頻度差を表示）。
**Z5**（情報）：`cuobjdump -xelf` で取り出したcubinを `readelf -S` にかけ、3バイナリの `.text.*`
セクションのサイズとオフセットを並べる（配置差の手がかり）。

### `*_README_append.md` との照合

### 事前登録（実測前に固定）

- **Z1（ハード静的）**：カーネル領域sha（コメント除去後 `4b9ce994…`）が403_r2と同一、コード領域バイト一致。
- **Z3（表明する予測）**：`<402>` の対は命令列が完全一致。成立なら+0.12%はコードではない →
  403_r2をそのまま採用（本番 N=21 109,59x／N=22 983,9xx）し、Z5の配置差を「未特定の残り」として
  記録する。**反証**（相違）→ 403-r2cでインライン指定の綴りを変え（`POT_FORCEINLINE`を外す等）、
  X0／X1のみ再測（約4分）。
- **Z4（表明する予測）**：`<403>` の対照対も命令列が完全一致。
- **Z5（情報）**：セクション一覧。

所要：nvcc＋cuobjdumpで約1分。GPUは使わない。
