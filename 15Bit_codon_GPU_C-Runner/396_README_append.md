## 396 — 律速要因を測り直す(ncuストール内訳)

### なぜいま測り直すのか

395cは本番を **133,192.071 ms（2:13.19）** で閉じた。r6での採用は交互
セッション内A/Bで検証済み（S1〜S4すべて成立、利得 0.299% / 400 ms）。

しかし400 msより重要なのは、**ものさしが変わったこと**である。

| | 以前 | 現在 |
|---|---|---|
| セッション内反復 | 0.29% | **0.009〜0.029%** |
| セッション間再現 | ±1.6%（394c） | **0.005%** |

このカーネルに対する過去の最適化判断は、すべて 0.3〜1.6% のものさしで
下されている。**「どこが律速か」という絵そのものが測り直しに値する。**

396は機能を一切変えない。成果物は「速くなったms」ではなく**ストール理由の
順位表**であり、それが397で何を試すかを決める。

### 測る前に潰す2点

**1. 代理入力は本番を代表しているか。**
N=21フル実行は133秒で、ncuのリプレイには載らない。レコード数を削るが、
削ると `k_per_thread` が変わる（本番は 2,025,282 / 25,600 = **79.1**）。
ループ回数も分岐挙動も変わる。

したがってハーネスは **ncuなしで** k = 1,2,4,8,16 を掃引し、レコードあたり
マイクロ秒が本番値 **65.765 µs/record** と1%以内で一致する最小のkを選ぶ。
どのkも合格しなければ**プロファイルは取らずに停止する**。代表していない
代理は、自信に満ちた誤った順位表を生む。順位表が無いことより悪い。

**2. 測定のコストを先に測る。**
セクション数からncuのリプレイ回数は予測できない。1セクションのパイロットを
先に走らせ、その実測から総所要を外挿する。予算（既定900秒）を超えるなら
自動で代理を1段小さくし、**その旨と「較正帯から外れた可能性」を明示して**
続行する。ぶら下がらない。

### 記録すべき注意 — ncu自身がGPUを占有する

ncuはCUDAコンテキストとデバイスメモリを持つ。395cで、**コンテキスト数と
デバイス占有はこのカーネルを0.3〜10%動かす**ことが分かっている。したがって

> **プロファイル中の壁時計を、本番のタイミングと比較してはならない。**

396が読むのはカーネル単位のカウンタと比率だけである。ハーネスはncu実行中の
compute-appsを5秒ごとに採取し、ncu自身の占有をログに残す。

### 事前登録予測（実測前に固定）

1. **T1**: k ≤ 16 のどこかで µs/record が 65.765 の ±1% に収束する。
   収束しなければ代理は不成立で、396-r2で別の縮小法（層化抽出など）を
   設計し直す。
2. **T2**: アンカー `-g 21 21` が **133,192 の ±0.1%**、かつ
   `extra_ctx=1`。外れればセッションが本番状態になく、以下のプロファイルは
   別の機械を記述していることになるので停止する。
3. **T3**: メモリスループットはピークの **5%未満**。本カーネルの全DRAM
   往復は入力57 MBを1回読むだけで、133秒に対し実効0.4 MB/s。帯域律速で
   ないことをカウンタで確認する。
4. **T4（本リビジョン最大の情報量）**: 支配的なwarpストール理由は
   **分岐解決系**で、warpストールサイクルの **25%以上** を占める
   （394a時点の知見の追認）。
   **反証されれば律速要因は移動しており、397は最適化ファミリを変える
   必要がある。** ハーネスはこの判定を順位表の直後に出力する。

### ビルドの変更点

`-lineinfo` を追加した。ncuがストールをソース行に帰属できるようにするため
で、`-O3` の最適化には影響しない。

### 成果物

- ストール理由の降順表（各理由のシェア%付き）
- SM／メモリ利用率、発行スロット、達成オカパンシー、分岐効率、命令ミックス
- `396_profile.ncu-rep`（Nsight Computeで開ける生レポート）

397の候補はここから選ぶ。

### 四点の同一性

- `396_kernel_maxd14.cu`: r6のリネーム。最初の `#include` 以降は
  **バイト一致**（コード領域全体のsha256 `c5dbde3f1002229b…`）。カーネル
  領域は395a r2以来不変（`ebd7f523deb59134…`）。
- `396Py_kernel_maxd14_final.py`: r6Pyからの差分は**実行行3行**
  （`VERSION_TAG` / `REV_TAG` / テーブル）。r6で採用した
  `env_prefix="NQ_EXTRA_CTX=1 "` はそのまま維持する。

```
STATIC_ONLY=1 bash 396_validate.sh   # OK=17
              bash 396_validate.sh   # 約20〜30分
SKIP_ANCHOR=1 bash 396_validate.sh   # アンカー2.5分を省く(非推奨)
```

**ncuの権限**について。カウンタが管理者限定になっている場合、ハーネスは
`ERR_NVGPUCTRPERM` を検出して、sudo実行か、恒久設定
（`options nvidia NVreg_RestrictProfilingToAdminUsers=0` を
`/etc/modprobe.d/` に置いて再起動）のどちらかを案内して停止する。
19分を費やす前に、権限プローブが3秒で判定する。
