## 405 — `col` に盤外ビットを立てて持つ：`nf` を1命令に（F）

### 静的読み（2026-10-05、404_r3の `<403>` ループ130命令、GPUゼロ）

- **Cと同じ「2段判定」はメインループに残っていない。** 残る判定はどれも条件1つを1回で見ている
  （future_checkと子のjマークは同じ `1 << depth` を共用）。ルートの高速経路の2段はタスクごとに1回なので対象外。
- **`nf = bm & ~(nld | nrd | ncol)` が3命令**：LOP3 `0xfe`（3入力OR）／LOP3 `0x33`（NOT）／LOP3 `0xc0`（`& bm`、P0）。
  future_check側の同じ式は2命令（`0xfe`＋`0x0c`）に融合されているのに、ここはptxasがNOTをどちらの隣にも
  融合していない。`<402>` も同じ。この3命令は `avail → bit → nld/nrd → nf → avail` の反復をまたぐ鎖の上にある。
  README該当なし。

### 405の変更

`cur_col` に盤外ビットを立てて持つ（`col | ~bm`）。`ncol` が `~bm` を含むので、
`nf = ~(nld | nrd | ncol)` は従来の `bm & ~(…)` とビット一致し、3入力LOP3 1本になる
（インラインPTX `lop3.b32 … 0x01`。gccのCPUハーネスではCの綴り）。

| 場所 | 変更 |
|---|---|
| 初期化 | `nbm = ~bm`、`cur_col = root_col \| nbm`、`depth_base = popc((root_col \| nbm) & フィールドマスク)` |
| ステップ | `nf` を `lop3 0x01` に |
| pop（両レイアウト） | `colm = フィールド & マスク`、`cur_col = colm \| nbm`、`cur_depth = popc(colm) − depth_base` |
| push（両レイアウト、ルート・メインの2サイト） | `cur_col` をフィールド幅にマスク |

future_checkとルートの高速経路は不変（`bm &` は冗長になるだけで正しい）。カーネルは診断D2と同じSASS。

- `.cu`：404_r3比 コード領域 **removed=10 added=15**。404_r3に生成器（Fa+Fm）を適用した結果とバイト一致。
  kernel sha `4600f963`。
- `.py`：404_r3Py（本番）の純粋リネーム、実行行3行。
- ハーネス：`405_validate.sh`。

`<403>` は実命令464→466、ループ130→130（ステップ−1、pop＋1）。`<402>` は462→465、ループ129→131
（pushのマスクが融合せず＋2）。402レイアウトは既定では使われない。

### 恒久ルール（追加）

- 命令数が同じでも、命令の種類が変われば時間は変わる（Pa+Ta：+0.82%）。「同数だから中立」とは読まない。
- インラインPTXの `lop3` は述語を出せない。結果を分岐に使う箇所では、ISETPが1本増える前提で数える。

### この先

- 405が通れば、次は「分岐を早くする」方向の静的読み：`nf == 0` の分岐の手前に残る段（`nld`／`nrd` のシフト、
  マーク処理の合流）を数える。GPUゼロ。
- 空判定そのものを無くす案（スタックの底に `avail = 0` の番兵フレーム）は、フレームが160 Bを超え、
  ループの制御の形も変わる。制御の形は閉じた軸なので保留。
- 未解決のまま：Bがlayout 402で効かない理由、Cが効いた理由。今回の「分岐の深さ」の仮説と同根の可能性がある。
