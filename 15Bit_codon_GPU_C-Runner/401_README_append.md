## 401 — 崖の位置を測る。何も作らずに

### 400-r3で壁の正体が確定しました

カーブアウトは**無効**でした。ドライバは既にL1へ最大を割り当てています。

```
既定 effective_pref=-1 / NQ_CARVEOUT=0 -> effective_pref=0
stride 81,920: 10,729.669 -> 10,729.866 ms  (+0.002%)
L1ヒット率  :     85.96% ->     85.92%
```

K3・K4は私の予測が外れです。**しかし同時に載せた診断が、壁そのものを突き止めました。**

| stride | thr/SM | 作業集合 | L1ヒット率 | L2読出セクタ | occ | warps/sched |

そして律速要因が反転します。

**オカパンシーの梃子は機構としては効きました**（warps/sched 2.44 → 7.71）。
**しかし椅子を埋めた瞬間、DFSスタックがL1から溢れました。**

> **208バイトのフレームが、オカパンシー軸の門番です。**
> そして本番点ではローカルメモリは全く問題になっていません（ヒット99.48%、
> long_scoreboard 12.9%）。問題は椅子が2.44しか埋まっていないことだけです。

### 401が問う、ただ一つのこと

400-r2/r3が測ったstrideは**崖の遥か先ばかり**で、手前を一度も刻んでいません。
詰め替えを書く前に、これを知る価値があります。

> **作業集合がまだ収まっている範囲で、10 warps/SM を超える構成の中に、
> 320スレッドのベースラインより速いものが1つでもあるか。**

- **ある** → フレーム半減はその範囲を広げる。402で実装する価値が確定
- **無い** → **このアルゴリズムではオカパンシーはそもそも効かない。**
  どれだけ上手く詰め替えても無駄になる

**約12分、コード変更ゼロで、どちらかが判ります。** 397の失敗（診断が終わる前に
手を動かした）を繰り返さないための一手です。

### 事前登録予測（実測前に固定）

1. **L1**: MB=800 が 2,153.8 ms の ±0.5%（セッションアンカー）。
2. **L2**: 時間は作業集合に対して**単調増加**。非単調なら容量以外の機構が
   混じっています。
3. **L3**: L1ヒット率は単調減少し、99%を割る点が **80〜120 KB** のあいだ。
4. **L4**: 「時間がベースライン+5%を超える点」と「ヒット率が99%を割る点」が
   掃引1ステップ以内で一致する。**悪化がミスで説明できること。**
5. **L5（本リビジョンの決定事項）**: **表明する予測——10 warps/SM を超える
   構成のうち少なくとも1つがベースラインより速い（0.5〜3%程度）。**
   1つも無ければ**オカパンシー軸は死に、402で詰め替えを書いてはなりません。**
   その場合、wait 48% は「ワープを増やす」ではなく「内側ループの依存鎖を
   短くする」方向で攻めることになります。

全走行がオラクルゲート下です。`MAX_BLOCKS` を変えても同じレコードを再分割する
だけなので、答えは動いてはなりません。

### 104バイト案 — L5が通った場合にのみ着手

397で `rd` が逆算不能としたのは `>> step` で下位が失われるからでしたが、
**`step` は1〜3、失われるのは最大3ビット**です。保存すれば復元できます。

```
現行保存 : ld(20) rd(32) col(21) avail(21) depth(4)  = 98ビット
bit方式  : bit(21) rd_lost(3) avail(21) depth(4)     = 49ビット
```

`bit` があれば `col = col_child & ~bit`、`ld = (ld_child >> step) & ~bit`、
`rd = ((rd_child & ~bK) << step | rd_lost) & ~bit` で復元できます。
`step` と `bK` はその階層の `block_code` から導けるので保存不要です。

**49ビット = 1ワード。フレーム 208 → 104 バイト、ちょうど半分。**

ハーネスは測定した「99%を保つ最大作業集合」から、**104バイトなら何 warps/SM
載るか**を自動で計算して出力します。着手はその数字を見てからです。そして着手
したら、**397を止めたのと同じ全2,025,282レコードのバイト一致ゲート**を先に
通します。

```
STATIC_ONLY=1 bash 401_validate.sh   # OK=12
              bash 401_validate.sh   # 約12分
NPROF=20 NCONF=21 bash 401_validate.sh   # 本番規模
```
