### 403-r6 綴り探索の結果（コンパイルのみ、GPUゼロ）

403_r5の `.cu` からpopの `cur_ld` 1行だけを差し替えた7変種。全変種で `<402>` は402_r5と一致、
ptxas 160 B／spill 0／40レジスタ、`<403>` 496命令。

| 変種 | `<403>` sha | popのld |
|---|---|---|
| v0 `& ~1u`（r5） | `fd6f41b2` | SHF → LOP3(`0x1ffffe`) → LOP3(`0xf8`)：**3段** |
| v1 XOR選択 | `fd6f41b2` | 同上（SASS完全一致） |
| v2 定数マスク | `fd6f41b2` | 同上 |
| v3 戻しシフト | `fd6f41b2` | 同上 |
| v4 64ビット選択 | `fd6f41b2` | 同上 |
| v6 マスク変数 | `fd6f41b2` | 同上 |
| **v5 インラインPTX `lop3.b32 0xD8`** | **`a8c1fffa`** | **SHF → LOP3(`0xb8`)：2段** |

- C綴り6変種はSASSが**バイト一致**：フロントエンドが同じ式に正規化し、ptxasは2つのLOP3を融合
  しない。綴りでは動かせない。
- v5は2つのLOP3が1つ（LUT `0xb8`＝マスクビットでの選択）になり、他は分岐アドレス以外すべて同一
  （末尾の整列NOPが1つ増えて合計は496のまま、実命令は495）。
- pop = 5命令、深さは col 1／avail 2／**ld 2**／rd 0 — `<402>` と同じ形。

（395bの「ptxasはくじ引き」に対して：今回は並べ替えが起きず、差分がその1命令だけに閉じている。）

### 403-r6の分割

- `.cu`：403_r5からpopの1行を9行ブロックに（`a43` 一時変数、`#ifdef __CUDACC__` で `asm`、`#else`
  はgccのCPUハーネス用にr5と同じC綴り）。コード領域 403_r5比 **removed=1 added=7**、kernel sha `850009f1`。
  402分岐不変。
- `.py`：403_r5Py（本番）の純粋リネーム、実行行3行。
- ハーネス：`403_r6_validate.sh`。tarから実行ファイルを除外（r6探索のtarが1 MiBで切れた原因は
  私が変種バイナリを同梱したため）。

### 事前登録予測（実測前に固定）

効果量は小さいはず（最長鎖から1命令、発行スロット−1）。r5の−0.44%は8命令分だった。

1. **P1（表明）**：X6/X5 ≤ 0.998。**反証**：≥ 0.9997（|差|がN=22フロアの10倍以内）。間はグレー。
2. **P2（表明）**：Z6/Z5 ≤ 0.998。反証 ≥ 0.9997。
3. **P3（ハード）**：G22 オラクル一致・`layout=403`。情報：G22 対 983,153。
4. **P4**：全セル1710±2%。

**採用則**：S0〜S3・Y2・Y3・X6一致・P1成立・P3 で `403_r6` が本番（N=22本番値＝G22、N=21不変）。
反証なら採用せず（403_r5のまま）、「ld鎖の1段は測れない＝残る+2.3%はpopの鎖ではない」と記録。
グレーはsuzuki判断（結果同一・コードは厳密に短いので、小さくても本物なら採る価値はある）。

所要：約55分（`SKIP_X5=1` で約38分、`SKIP_G22=1` でさらに−16.5分）。

```
STATIC_ONLY=1 bash 403_r6_validate.sh      # OK=15
              bash 403_r6_validate.sh      # 約55分
SKIP_X5=1     bash 403_r6_validate.sh      # 約38分
```

**事前条件**：`403_r5_kernel_maxd14.cu`／`403_r5Py_kernel_maxd14_final.py`／`403_r5_kernel_maxd14`
（無ければ `.cu` から再ビルド）、`402_r5_kernel_maxd14`（S2参照）、`rev386_validation_helpers.py`、
N=21／N=22入力。`SKIP_X5=1` のときは `403_r5_validate_*/bins/X1_results.bin` が必要。

### この先（403-r6の結果に関わらず）
