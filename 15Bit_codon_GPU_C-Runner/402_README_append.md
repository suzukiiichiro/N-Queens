## 402 — DFSスタックのフレームを16→12バイトに（395a r2以来初のカーネル変更）

### 401-r4が揃えた前提（2026-09-28、全セル2ctxホルダー状態、全セル1710 MHz）

| セル | kernel_ms | H0比 |
|---|---:|---:|
| H0（ホルダー1、ctx=0、MB=800） | 133,565 | 395c-r4 D1比 +0.003% |
| H1（＋自プロセスctx） | 133,564 | −0.001% → **自プロセスctxは不活性** |
| H2（ホルダー2） | 133,181 | **−0.288%** → 切り欠きは本物の第3ctxで戻る |
| L720（9 w/SM） | 144,058 | **+7.86%** |
| L880（11 w/SM、71.5 KB） | 136,867 | +2.47% |
| L1280（16 w/SM、104 KB） | 274,814 | +105.8% |

**L1に収まっている限りワープ増は急に効き、800（65 KB）がL1の天井。** 208バイトの
フレームがオカパンシー軸の門番（401）で、L1から出ずにワープを足す方法はフレームを
縮めることしかない。本番の現在値は133,56x〜133,59x（`NQ_EXTRA_CTX=1` は現状態では
不活性、害なし）。恒久ルール採用：**直接実行の状態は外部ホルダーで作る／梯子の比較は
同一ctx状態の中でしか行わない**。

### 402のレイアウト — そして397がなぜ落ちたか

```
旧 (u64×2): ld | rd<<32 ,  col | (avail | depth<<27)<<32           = 16 B
402:  word A (u64) = (ld & M21) | col<<21 | avail<<42               = 63ビット
      word B (u32) = rd（32ビット全部）
      depth        = ローカルメモリに置かない。レジスタ1本に4ビット×13段をLIFOで
```

- **ldの盤面より上のビットは死んでいる**：全使用箇所が左シフト後に `bm` でマスク
  される（398の解析）。落としてよい。
- **rdの上位ビットは降りてきて制約になる**ので全幅で保存する。397はここをマスクして
  解が 427,786,151,034 に増えた。
- 401ノートの「子の状態から親を逆算する」案は**不可能**だった。pop時点の現在ノードは、
  popするフレームの子ではなく任意の子孫である（兄弟の残っていないノードはpushされ
  ない）。逆算に必要な情報が無い。
- depthをレジスタに出すことで 98→95ビット、12バイトに収まる。**ローカルアクセスは
  push 2 / pop 2 のまま**（リクエスト数・発散は不変。減るのはセクタ数だけ）。
- 3×21＝63ビットなので **N≤21専用**。N=22は3×22＝66で別の分割が要る。両方の `main()`
  は argv を読んだ直後、ファイルを開く前に N>21 を `rc=3` で拒否する。**`-g` を22以上
  で回さないこと。**

手元検証：合成250レコード（解51,488,002、スタック深さ12段まで）で401-r4版と402版の
CPU出力がバイト一致。N=22は rc=3 で拒否。コード領域差分 **removed=21 added=46**、
カーネル領域sha256は `ebd7f523…` から変わる（変わったこと自体をゲートする）。

### 予算

65 KB ÷ 156 B ＝ 426 thr/SM ＝ **13 w/SM**（BLOCK=32、MAX_BLOCKS 1040）。
12 w＝58.5 KB、14 w＝68.3 KB、16 w＝78 KB。

### 事前登録予測（実測前に固定）

1. **V5**: E0 が 133,565 の ±0.15%（401-r4 H0）、`free_mb=22,018±2`。
2. **V6（表明する予測）**: |E1 − E0| ≤ 0.5% —— pack/unpackのALUは無料で、フレームが
   小さいだけでは10ワープでは速くならない。**対立仮説**: E1 ≥ E0 + 1% → 393-8が
   結局正しく、掃引はまずこの分を返す必要がある。
3. **V7（本リビジョンの決定事項。表明する予測）**: min(P960, P1040) ≤ E0 − 3%。
   点予想は約−8%（r4の9→10段が−7.3%。傾きが寝ることを見込んで割引）。
   **反証**: どれも E0 − 1% を下回らない → L1内でも10ワープを超えると効かない。
   この軸はN=21で閉じる。
4. **V8**: P1120 と P1280 は P960/P1040 の最良より遅い —— 崖はワープ数ではなく容量
   （約65 KB）で、フレームに合わせて予算どおりに動く。外れれば予算モデルが誤り。
5. **V9**: 全セルの平均SMクロックが1710の±2%。

**採用則**: 本リビジョンで本番既定は何も変えない。勝ったMBは 402-r2 の交互A/B
（≥2反復）の候補とする。
