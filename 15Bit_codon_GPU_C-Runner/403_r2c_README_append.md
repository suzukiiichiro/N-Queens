## 403-r2c — 402_r5と同一SASSになる綴りをコンパイルのみで探す

### 403-r2bで確定したこと（2026-09-29）

Z3・Z4とも反証。ただし差の中身は明快：

- **Z3**（402_r5 対 403_r2 `<402>`）：命令数496・オペコードの多重集合・分岐先は同一。差は
  **63命令**で、レジスタ名の付け替え（R29↔R31など）、可換 `LOP3` のオペランド順、基本ブロック内の
  独立命令の並べ替えのみ。集中箇所は #320〜430＝**402のpush/pop**（`0x1fffff` マスク、`STL.64`）。
  403で「pop直後の依存鎖」が効いたのと同じ場所のスケジュール差。+0.123%はこれで説明がつく。
- **Z4**（403 対 `<403>`）：504命令、差40命令、同性質。こちらは逆に**速くなっている**
  （X3 +2.40% 対 403単体 +2.79%）。並べ替えは損にも得にもなる。
- **Z5**：両 `.text` とも128 B整列・同サイズ（0x1f00／0x1f80）。配置は関係なし。

読み：意味的なコストではなく、コンパイル単位（カーネル2実体・テンプレート文脈）が変わったことによる
ptxasの同点判定の差＝決定性の問題。

### 403-r2cの分割

`.cu` は403_r2の純粋リネーム（コード領域バイト一致、カーネル領域sha `4b9ce994…`）で、ハーネスが
これを機械的にパッチして変種を作る（`/tmp` と `$LOGDIR/variants/` に保存、各変種はCとしてもビルド
できることを静的に確認）。全変種を本番フラグ（`-O3 -arch=sm_86 -lineinfo`）でビルドし、
`cuobjdump -sass` を402_r5（`<402>`側）と403（`<403>`側）に対して命令列完全一致で比較する。

| | 内容 |
|---|---|
| **C0** | 対照：402_r5をソースから再ビルドし、既存バイナリとSASS一致（nvccの決定性）。不一致なら探索は無意味なので停止 |
| **P1** | 情報：V0の `<402>` エントリのPTXと402_r5のPTX（レジスタ・ラベル名を正準化、`.loc` 除去）。ptxas以前に違うのか、ptxasだけの差か |
| V0 | 現状（403_r2） |
| V1 | `POT_FORCEINLINE` を空に |
| V2／V3 | 明示実体化を `<402>,<403>`／`<403>,<402>` の順で追加 |
| **V4** | テンプレートをやめ素のカーネル2つ。402側は402_r5と**同じマングル名** `kernel_dfs_iter_gpu_maxd14`、403側は `_l403` |
| V5 | V4＋`POT_FORCEINLINE` 空 |
| V6／V7 | 診断：`<402>` のみの単実体（403カーネルがcubinに無い）／＋インラインなし。「第2カーネルの存在」と「process_one_taskの変更」を切り分ける。N=22は走れないので勝者にはならない |

**勝者**：V1〜V5のうち `<402>` のSASSが402_r5と完全一致（分岐先込み）する最初のもの。`<403>` も
403と一致するものがあれば優先。勝者のソースを `403_r2c_kernel_maxd14.winner.cu`、バイナリを
`403_r2c_kernel_maxd14`（`.py` のテーブルが指す名前）に書き出し、納品 `.cu` との差分も保存。
