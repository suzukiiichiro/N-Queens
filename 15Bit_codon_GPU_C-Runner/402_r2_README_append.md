### r2が変えるもの — 本番1行

`A10G_FINAL_DEFAULT_MAX_BLOCKS: 800 → 960`。`-g` はこれを `NQ_MAX_BLOCKS=960` として
CRunnerへ渡す（395a以来の経路、変更なし）。`.cu` は402のリネーム（`#include` 以降
バイト一致）。Pyの実行行差分は**4行**（`VERSION_TAG`／`REV_TAG`／テーブル／既定値）。

採用は402の採用則どおり**交互A/Bを通してから**。A/Bの勝者が960でなければ、数値は
採用しつつ既定の差し替えは402-r3（Py実行行3行＋G21一回）で行う。

### 事前登録予測（実測前に固定）

1. **Q1（ハード）**: A800の平均が 129,524（402 E1）の ±0.15%、`free_mb=22,018±2`。
   落ちたら状態が402と違い、以下は読まない。
2. **Q2**: 各構成の2回が互いに0.05%以内（ノイズフロア0.01%台）。
3. **Q3（表明する予測）**: 最小はA960。A880はA800とA960の間。A1040は116,102の±0.3%。
   **対立仮説**: A880 < A960 → 最適は11 w/SM。
4. **Q4（採用則）**: 勝者が A800 − 10% 以下で、Q2を満たすとき採用する。勝者が960なら
   この `.py` の既定がそのまま立つ。880か1040なら数値は採用し、既定は402-r3で差し替える。
5. **Q5**: G21 が A960 平均（勝者が960でなければ勝者の平均）の ±0.30%、CRunnerログに
   `[gpu-config] MAX_BLOCKS=960`、`dispatch.log` に `NQ_MAX_BLOCKS=960`。
   **反証**: 既定が経路に乗っていない → 採用無効。
6. **Q6**: 全セルの平均SMクロックが1710の±2%。

### 注意

- 402-r2バイナリは **N≤21専用**。素の `-g` はN=22で rc=3 になり止まる（想定どおり）。
  N=22の分割は403で別設計（3×22＝66ビットは今の形に入らない）。
- `env_prefix` の `NQ_EXTRA_CTX=1` は現状態では不活性（401-r4 H1）。害が無いので残す。
- 413 msの切り欠き（第3の実プロセスctx）は、MBが変わると `free_mb` の谷も動くので、
  960で改めて測る必要がある。本リビジョンでは扱わない。
