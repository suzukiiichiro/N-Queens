## 408 — マークの腕を code 別の64ビット表1個で引く（T2）

407の結果と採用は `407_results_README_append.md` に記録済み（N=21 99,214 ms／N=22 868,287 ms）。

### 静的読み：407の `<403>` ループ121命令に残る分岐領域（2026-10-06、GPUゼロ）

| 領域 | 中身 | 命令数 | 頻度（ステップ比） |

| | マークなし腕：`bit<<1`、`bit>>1`、nld、`cur_x\|bit`、nrd、LOP3 | 6 | 52% |

| 降下領域（B5） | 退避MOVが4本（avail・col・rd・ld）。pushが親の状態を後から読むため消せない | — | 61.1% |

マークあり腕28命令のうち15本は「定数をレジスタに置く→block_codeでシフト→`&1`」の5組。407のMはこれを深さ別の表に
タスクごとに前計算して腕を14にしたが、14回の表作りループが展開されてレジスタ55本になった。**block_codeは3ビット
（使われるのは1〜5）なので、表は深さ別ではなく code 別の即値1個で足りる**：前計算なし、レジスタ増なし、ニブル抽出は
共有のまま（M／M2で `(7 << 4d) & schedule64` の5命令に膨らんだのは block_code が死んだため。T2では生きている）。

### 408の変更

```
uint32_t stepu = 2u + ((OP_STEP3_MASK >> block_code) & 1u);      const uint32_t mt = (uint32_t)(MARK_T64 >> (block_code * 8u));
uint32_t addvu = (OP_ADD1_MASK >> block_code) & 1u;               const uint32_t stepu = mt & 3u;
uint32_t bLiu  = ((OP_BL1_MASK >> block_code) & 1u)          →    const uint32_t bKu = ((mt >> 4) & 3u) * n4;
               | (((OP_BL2_MASK >> block_code) & 1u) << 1);       nld = ((cur_ld | bit) << stepu) | ((mt >> 2) & 3u);
uint32_t ktu   = ((OP_KN3_MASK >> block_code) & 1u)               nrd = ((cur_rd | bit) >> stepu) | bKu;
               | (((OP_KN4_MASK >> block_code) & 1u) << 1);
uint32_t bKu   = (n3 & (0u - (ktu & 1u))) | (n4 & (0u - (ktu >> 1)));
nld = ((cur_ld | bit) << stepu) | addvu | bLiu;
nrd = ((cur_rd | bit) >> stepu) | bKu;
```

`MARK_T64 = 0x0202062B17062202`：byte(code) = (kn3<<1 | kn4)<<4 | (addv | bL1 | bL2<<1)<<2 | step。6つの `OP_*` マスクから
生成器が作る（マスク値もソースと照合）。bK = kn3·n3 + kn4·n4 = (2·kn3 + kn4)·n4 は両ホストとも `n3 = 1 << (N-3)`、
`n4 = 1 << (N-4)` を渡していることによる（Mと同じ前提。N=8〜22・全code・乱数の ld／rd／bit で元の式と全一致を確認、
本番の等価はY2と `results.bin` のバイト一致で見る）。

ほかは不変：ニブル抽出、マークなしの腕、`nf` の2つのLOP3、`cur_x`、future_check、jマーク（407 J）、push／pop、
レイアウト選択。ルート経路（タスクごとに1回）は `OP_*` の綴りのまま。

- `.cu`：407比 コード領域 **removed=11 added=5**。407に生成器（T2）を適用した結果とバイト一致。kernel sha `ab483e70`。
- `.py`：407Py（本番）の純粋リネーム、実行行3行（VERSION_TAG、REV_TAG、CRunnerEntry）。
- ハーネス：`408_validate.sh`。

### 恒久ルール（追加）

- 同じ式でも、ptxas は綴りを正規化する（`(x != 0)` と `min(x, 1)` が同一SASS）。述語付きMOVを避けたいときは
  綴りを変えるのではなく、値の持ち方（何を状態として持ち越すか）を変える。
- ローカルメモリへのストアは、頻度を増やすと時間に直接出る（Pu：STL 2本を27%→61%のステップで +63%）。
  「無条件にしておけば分岐が消える」はストアには当てはまらない。

### この先

- マークあり腕は14命令になった。残りは `step` のシフト2本・`lo2`／`kt` の抽出・IMAD。表の byte に `step` を
  そのままシフト量として置けるか（`mt & 3` を省く）は綴り探索から。
- 降下領域の退避MOV 4本（avail・col・rd・ld）は「pushが親を後から読む」ことに由来する。pushを「子の計算より前」に
  動かすと素通りのステップ（34%）でも書くことになり、Puと同じ罠（+63%）。この4本は現状の形では触れない。
- M系（深さ別の表）はT2で代替され、閉じる。
