### ビット勘定（静的読み。`build_soa_for_range` と `process_one_task` から）

403 の勘定（col 22＋avail 22＋ld 21＋rd 31＝96）は N=23 で 23＋23＋22＋31＝99。ソースの不変量で 2 つ戻る：

| フィールド | 根拠 | N=23 の幅 |
|---|---|---:|
| col | ホストが `col \|= ~small_mask`（`small_mask=(1<<(N−2))−1`）→ **bit N−2・N−1 は常に 1**。以後 col は `\| bit` で増えるだけ | 21 |
| avail | `free = bm & ~(ld\|rd\|col)`、以後 `nf = ~(…\|ncol)` → col の定数ビットは**常に 0** | 21 |
| ld | bit N−1 は盤外（403） | 22 |
| rd | bit 0 は死に（403）。盤外に出る唯一の項 `(1<<(N1−j)) << (N2−start)` は `j ≥ 2N−33−start` のときだけ入り bit `2N−3−j−start ≤ 30`、生の rd は u32>>1、bK＝kt·n4 は bit N−3 以下、DFS は rd を右にしか動かさない | 30 |

21＋21＋22＋30 ＝ 94 ≤ 96。

```
423:  A (u64) = col[0..20] | avail[0..20] << 21 | ld[1..22] << 42     （64 ビットちょうど）
      B (u32) = (rd & ~1) | ld[0]                                       （403-r7 と同じ綴り）
pop:  colm = A & 0x1FFFFF ; cur_col = colm | nbm2   （nbm2 = ~bm | (bm & ~(bm >> 2)) ＝ 盤外＋定数 2 ビット）
      cur_avail = (A >> 21) & 0x1FFFFF ; cur_ld = lop3(A >> 41, B, 1, 0xD8) ; cur_rd = B
```

403b と同じ形（フィールドごとにシフト 1 と LOP3 1）なので、`<423>` のループは `<403>`（108）＋0〜2 命令の見込み（S4 で記録、表明 ≤110）。
rd の bit 0 に ld[0] が、cur_rd の読み戻しに残るのは 403 と同じ（右シフトで消える）。

### 祖先段数：14 段で 168 B

N=23 は `required_maxd=15`（389 の bench_mode=34、全 44,271,796 件）＝スタック最大 14 段。`PACK423_ANCESTOR=14` → 14×12＝**168 B**／スレッド
（12 ブロック/SM ＝ 64,512 B、L1 65,536 B の内側。15 段 180 B なら 11 ブロック/SM）。上限はゲートで守る：413 フィルタが全件の深さ
ヒストグラムを出し、最大深さ >15 ならハーネスが止まる（H1）。CPU ハーネスは溢れで abort。ファイル名の「maxd16」は系統名で、この
バイナリのテーブル項目は `maxd_max=15`（N=24 は入力自体が 12 B に入らない：22＋22＋23＋30＝97）。

### 手元検証（GPU ゼロ、サンドボックス）

合成レコード（ランダムな完全解の先頭 q 行を前置、rd の盤外ビット N〜N+7 に乱数、N=23 は depth 15・q=5、N=22／21 は depth 14、各 200 件、
全件が非ゼロ）で、413 の CPU ハーネス（auto／`NQ_LAYOUT=423`／402）が **392 と 411 の CPU ハーネスにレコード単位でバイト一致**。
N=24 rc=3、`NQ_LAYOUT=403` で N=23 rc=3。実レコードでの等価（Y2）はハーネスで取る。
