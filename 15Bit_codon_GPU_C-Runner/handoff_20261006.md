## 3. 分かったこと

- **同一SASSのふらつき（10/5から0.04〜0.1%）の原因はSMクロックの熱絞り。** 70〜74 ℃で1695 MHzに落ちる瞬間があり、
  時間 ∝ 1/クロック（408の3走行：時間比1.0038、クロック比1.0036）。クロック1710で正規化すると±0.03%で合う。
  ただし同一SASS・1710平らでも 97,829 対 97,913（0.09%）の残差はある。
- **Mの利得は前計算ではなく腕の長さから来ていた。** T2（code別の即値、レジスタ37）が M（深さ別の表、レジスタ55）と
  同じ−0.9%。block_code は3ビットなので表は即値1個で足りる。
- **ローカルメモリのストアを増やすと時間に直接出る**（Pu：STL 2本を27%→61%のステップで +63%）。
  pushガードは数字つきで閉鎖。
- **popの1命令はループ全体の1命令と同じ重さ**（X2：pop内+1命令で+0.48%）。ロード後の鎖を5→3段にしても効かない。
  popは「命令を足さない」以外に触れない。
- **ptxasは綴りを正規化する**（`(x != 0)` と `min(x, 1)` が同一SASS）。述語付きMOVを避けるには値の持ち方を変える。
- **`LDL.64`／`STL.64` のレジスタ対は整列が必要**。64ビット値をループで持ち越すと戻り辺でコピーが出る（C：MOV+11）。
- R2の律速の仮定（マーク付きの頻度がN=22で低いので利得は小さい）は外れた：N=22 −1.67%、N=21 −1.19%。
  頻度だけでは利得は決まらない（407のJも同じ向きの逆転）。
- 両用関数（`__host__ __device__`）からデバイス組み込み（`__popc`、`__byte_perm`）は呼べない。インラインPTXで綴る。

## 4. 恒久ルール（今日追加）

1. ハーネスは `norm_ms = kernel_ms × sm_mean / 1710` を併記し（クロック標本5秒・busyのみ）、読みは正規化値で。
   正規化後も0.1%の残差があるので採用の帯（≤0.998）と事前登録の幅はそのまま。
2. ptxasは同じ式の綴りを正規化する。述語付きMOVを避けたいときは綴りではなく値の持ち方を変える。
3. ローカルメモリへのストアは頻度を増やすと時間に直接出る。「無条件にすれば分岐が消える」はストアには当てはまらない。
4. 64ビットの値（`LDL.64`／`STL.64` の対）をループで持ち越す綴りは、戻り辺のMOVを呼ぶ。候補にする前に探索のMOV列を見る。
